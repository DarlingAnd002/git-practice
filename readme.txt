校园小铺购物系统
版本：V-0.1（双角色、商品归属、库存与历史订单版）

一、项目简介

本项目使用 Java 实现一个适合课堂团队合作演示的控制台购物系统。
用户注册时选择销售者或消费者；登录后，系统根据账号中保存的角色
自动进入相应菜单。销售者管理自己的商品和销售订单，消费者浏览商品、
使用购物车、结账并查询自己的历史购买记录。

本项目使用模拟结账，不连接真实支付平台。

二、运行环境与启动方法

1. 安装 JDK 17 或以上版本，需要同时具备 java 和 javac。
2. 项目不依赖第三方库，不需要安装 Maven 或 Gradle。
3. 源代码使用 UTF-8 编码。

方式 A：IntelliJ IDEA

打开 shopping 项目，设置项目 JDK 为 17 或以上。
打开 src/Main.java，点击 main 方法旁的运行按钮。
将运行配置中的 Working directory 设置为 shopping 项目根目录，
确保 IDEA 和脚本使用同一份本地账号、库存及订单数据。

方式 B：PowerShell

在 shopping 项目根目录打开 PowerShell，执行：

    .\run.ps1

运行全部自动检查：

    .\run.ps1 -Test

方式 C：手动编译与运行

如果系统禁止运行 PowerShell 脚本，可以在项目根目录执行：

    New-Item -ItemType Directory -Force build
    javac --release 17 -encoding UTF-8 -d build src/Main.java src/shop/*.java test/shop/*.java
    java -cp build Main

手动运行测试：

    java -cp build shop.ShopTest
    java -cp build shop.AuthTest
    java -cp build shop.CommerceTest

三、注册与登录

启动菜单：1 注册；2 登录；0 退出。

注册流程：
1. 输入账号，账号为 3–24 位英文字母、数字或下划线，不区分大小写。
2. 选择角色：1 销售者；2 消费者。
3. 输入密码并再次确认，密码为 8–128 个字符，区分大小写，保留空格。
4. 注册成功后回到启动菜单，选择登录。

登录只需要输入账号和密码，不需要再次选择角色。
同名账号不能重复注册，也不能通过重复注册覆盖已有角色。
退出登录后会话失效，用户回到启动菜单。

系统没有预设账号。请自行注册测试账号，不要使用个人常用密码。
系统终端支持隐藏密码；IDEA 控制台不支持隐藏时会提示输入可见。

四、销售者功能

1 我的商品：只显示当前销售者创建的商品、价格及库存。
2 添加商品：填写商品编号、名称、价格和初始库存。
3 修改价格：只能修改自己的商品价格。
4 设置库存：只能设置自己的商品当前可售数量，可用于补货。
5 我的订单：只显示包含自己商品的订单明细和自己的实收金额。
0 退出登录。

商品编号在整个商店中唯一，为 3–12 位大写字母或数字。
名称最多 60 个字符，不允许控制字符。价格必须为正数，
菜单允许最多 7 位整数和 2 位小数。
商品所有者自动取自当前登录账号，不能手动指定其他销售者。
销售者不能管理其他销售者的商品，即使知道商品编号也会被拒绝。

五、消费者功能

1 商品列表：查看所有销售者的商品、销售者账号、价格和当前库存。
2 加入购物车：输入商品编号和数量，重复添加会累加数量。
3 查看购物车：查看商品、数量、小计和当前可售库存。
4 修改/删除：设置商品的新总数量；输入 0 删除该项。
5 结账：输入优惠码，查看报价，输入 y 确认模拟购买。
6 历史购买记录：查看当前账号以前已完成的订单。
0 退出登录。

购物车按消费者账号隔离，不同消费者不能结算他人的购物车。
仅退出登录时购物车保留，整个程序退出后购物车清空。

六、库存限制

1. 每件商品的可售库存范围为 0–1000000。
2. 同一购物车每种商品累计数量为 1–99，且不得超过当前库存。
3. 新增加购、重复累加和修改数量都会检查库存；失败时保留原数量。
4. 库存为 0 时，商品列表显示 Sold out，不能继续购买。
5. 已在购物车中的售罄商品仍可删除。
6. 加入购物车不预占库存。其他人购买或销售者调低库存后，
   购物车原有数量可能超过当前库存；用户需要重新调整数量。
7. 报价和确认购买时都会重新检查库存，避免使用过期的库存信息。
8. 同一数据目录只允许一个商店进程运行，避免多个程序分别售出同一份库存。

七、折扣与结账规则

所有金额单位均为人民币，使用 BigDecimal 计算。

折扣顺序：
1. 原价小计满 100 元，整单减 10 元，仅减一次。
2. 输入 STUDENT10 后，在满减后金额的基础上再优惠 10%。
3. 优惠额四舍五入保留两位小数。优惠码留空表示不使用优惠码。

例如：小计 100.00 元，满减 10.00 元，再优惠 9.00 元，实付 81.00 元。

确认购买流程：
检查登录角色和购物车归属 → 重新检查报价及库存 → 保存扣减后的库存
和订单 → 保存成功后更新内存并清空购物车。

空车不能结账。取消结账时不扣库存、不记订单、不清空购物车。
若价格或购物车在确认前发生变化，需要重新确认报价。
若任何商品库存不足或文件保存失败，不会部分扣库或生成半笔订单。

跨销售者商品可一起结账，折扣按整单计算。
系统按各商品原价比例分摊实付金额，并处理分币舍入，
保证销售者实收金额之和严格等于消费者的整单实付金额。

八、订单与历史购买记录

消费者可以查看自己的整笔订单；销售者只能查看其中属于自己的商品行。
订单包含订单号、购买时间、消费者账号、商品编号、名称、销售者、
购买数量、当时单价、原价及优惠后的实付金额。
界面时间按 Asia/Shanghai（北京时间）显示。

销售者页面显示“本店实收”，不会展示其他销售者的订单商品和实收金额。
订单保存购买时的快照，后续改价、补货不会修改历史购买记录。
只有成功确认的模拟购买才会记入订单；没有待支付、退款或物流流程。

九、本地数据保存

    data/users.properties   账号、角色、随机盐与密码摘要
    data/store.properties   商品、归属、价格、库存和已完成订单
    data/store.lock         程序运行期间的数据目录锁

重启后账号、商品、库存和历史订单均保留。
购物车只保存在内存中，重启后清空。
新商店不预置商品，需要销售者先添加带库存的商品。
旧版本未落盘的商品无法恢复，原有账号文件继续使用。

库存与订单保存在同一份商店文件中，以原子替换方式提交，
避免保存失败时只扣库存却没有生成订单。
本地账号和订单文件不要上传仓库；data/ 已在 .gitignore 中排除。

十一、课堂演示示例

1. 注册销售者 seller_a、seller_b，以及消费者 buyer_a、buyer_b。
2. seller_a 添加 P01，名称 PenA，单价 50.00，库存 2。
3. seller_b 添加 P02，名称 BookB，单价 20.00，库存 1。
4. seller_b 尝试修改 P01，观察“只能管理自己的商品”提示。
5. buyer_a 尝试加入 3 件 P01，观察库存不足提示。
6. 改为加入 2 件 P01 和 1 件 P02，小计为 120.00 元。
7. 使用 STUDENT10：满减后 110.00，再优惠 11.00，实付 99.00 元。
8. 先取消结账，验证库存和购物车未改变；再次结账并输入 y。
9. 两个商品库存均为 0，列表显示 Sold out，再次加购会被拒绝。
10. seller_a 查看自己的订单，只显示 P01，实收 82.50 元。
11. seller_b 查看自己的订单，只显示 P02，实收 16.50 元。
12. buyer_a 的历史记录显示整单 99.00 元，buyer_b 看不到该订单。
13. 重启程序，验证商品、库存和历史记录保留。

十二、测试与团队协作

执行 .\run.ps1 -Test，当前版本共 96 项检查：
购物规则 21 项，账号与角色 21 项，归属、库存及订单 54 项。
覆盖非法输入、重复注册、错误密码、越权管理、购物车归属、
超库存、Sold out、最后一件商品争抢、订单隔离、重启恢复及保存失败。

建议按账号权限、商品库存、购物车订单、菜单文档与测试划分职责。
每个功能在独立分支开发，提交前运行测试，通过 PR 邀请其他成员审查，
审查通过后再合并到 main。不要提交 build/、out/、.idea/ 或 data/。

十三、安全设计与当前范围

密码采用 PBKDF2-HMAC-SHA256，600000 次迭代，
每个账号使用独立随机盐，不保存明文密码。
会话不能由调用方直接创建，退出登录后失效。
角色和商品所有权在业务层校验，不只依靠隐藏菜单选项。

当前为本地单进程课堂项目，注册时允许直接选择销售者。
没有商家审核、找回密码、登录限流、真实支付、退款和物流功能，
也没有面向多台电脑提供共享库存的在线服务端。
