# 校园小铺：Java 团队购物系统

一个无外部依赖的课堂最小项目。商店自选为 Campus Corner（校园文具店），提供商品浏览、添加商品、查看购物车、修改数量、删除商品及确认结账。界面用简单英文，避免不同终端中文编码造成乱码；文档用中文。

## 运行

安装 **JDK 17 或以上**（需要 `java` 和 `javac`，只有 JRE 不够）。在本目录打开 PowerShell：

```powershell
.\run.ps1
.\run.ps1 -Test
```

第一条启动菜单，第二条编译并执行规则测试。如果本机禁止执行脚本，可以直接使用：

```powershell
New-Item -ItemType Directory -Force build
javac -encoding UTF-8 -d build src/shop/*.java test/shop/*.java
java -cp build shop.ShopTest
java -cp build shop.Main
```

## 项目结构与职责

```text
src/shop/
  Main.java       菜单、输入校验反馈、确认结账
  Product.java    不可变商品信息
  Catalog.java    商品目录、按编号查询
  Cart.java       数量管理、购物车明细、小计
  Checkout.java   折扣计算、不可变收据
test/shop/
  ShopTest.java   金额、边界、非法输入和购物车状态验证
run.ps1           编译、启动或测试
```

数据流：用户菜单 → 商品目录 / 购物车 → Checkout 计算报价 → 用户确认 → 清空购物车。取消或无效优惠码会保留购物车。

## 折扣规则

- 所有金额均为人民币，商品价格固定在目录中。
- 原价小计达到 100 元，整单减 10 元，只减一次。
- 优惠码 `STUDENT10`：满减后再打九折，优惠额按四舍五入保留两位小数。
- 两种优惠可叠加，不含运费和税费；没有会员或登录条件。
- 每种商品累计数量 1–99；修改为 0 表示删除。空车不能结账。

示例：8 套 P02（12.50 元/套），小计 100.00，满减 10.00，再优惠 9.00，最终 81.00 元。

## 课堂演示步骤

1. 输入 `1` 浏览商品。
2. 输入 `2`，编号 `P02`，数量 `8`。
3. 输入 `3` 查看小计 100.00。
4. 输入 `5`，优惠码 `STUDENT10`，检查应付 81.00。
5. 输入 `n` 演示取消并保留购物车；再次结账输入 `y` 演示成功清空。
6. 尝试未知商品、负数量、非数字数量和空车结账，观察错误提示后菜单仍可使用。
7. 输入 `0` 退出；输入流结束也会正常退出。

## 团队合作建议

| 成员 | 负责模块 | 交接要求 |
|---|---|---|
| A | Product、Catalog | 稳定商品编号，维护价格 |
| B | Cart | 统一数量边界与删除行为 |
| C | Checkout、测试 | 先约定优惠顺序与金额样例 |
| D | Main、文档、集成 | 跑通演示和异常输入 |

人数少时合并职责。每个功能单独建 Git 分支，小范围提交；合并前让另一名同学检查修改并运行测试。修改折扣时同时更新样例、文档和测试，不要多人同时改菜单文件。

## 代码安全与范围

使用 BigDecimal 避免浮点金额误差；价格从内部目录读取；商品编号采用目录白名单；数量在购物车层校验，因此绕过菜单也不能写入负数或超限数量。只处理预期的输入错误，不向用户输出堆栈。商品、购物车返回的明细及收据保持不可变，避免外部修改内部状态。

这是单用户、单进程、内存中的结账模拟，退出后不保存，不连接真实支付或外部服务，也没有登录认证、库存扣减、并发控制和持久化订单。如果后续扩展成多人在线商店，需要另行设计服务端身份认证、权限、库存事务和订单存储。
