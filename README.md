# 校园小铺：Java 双角色购物系统

JDK 17 或以上，无第三方依赖。入口是 `src/Main.java`，在 IDEA 中运行它即可。

## 运行与测试

在项目目录打开 PowerShell：

```powershell
.\run.ps1
.\run.ps1 -Test
```

IDEA 的 Run Configuration → Working directory 请设置为项目根目录，保证与脚本读取同一份账号文件。源代码使用 UTF-8。若系统禁止脚本，可直接执行：

```powershell
New-Item -ItemType Directory -Force build
javac --release 17 -encoding UTF-8 -d build src/Main.java src/shop/*.java test/shop/*.java
java -cp build shop.ShopTest
java -cp build shop.AuthTest
java -cp build shop.CommerceTest
java -cp build Main
```

## 注册和登录

启动后只显示「注册、登录、退出」，必须登录后才能操作商店。

1. 选择注册，输入账号，选择 `1 销售者` 或 `2 消费者`，输入并确认密码。
2. 账号为 3–24 位英文字母、数字或下划线，不区分大小写；密码为 8–128 位，区分大小写且保留空格。
3. 注册后选择登录，仅输入账号及密码。系统根据已保存的账号自动读取角色，不再让用户选择角色。
4. 退出登录会使会话失效，回到注册/登录菜单。

| 角色 | 可用功能 |
|---|---|
| 销售者 | 我的商品、添加商品、修改自己的商品价格、设置自己的库存、我的订单、退出登录 |
| 消费者 | 商品列表、加入购物车、查看购物车、修改数量/删除、结账、历史购买记录、退出登录 |

按照课堂要求，注册者可以直接选择销售者。商品归属由添加商品时的登录账号自动决定。销售者只能列出并管理自己的商品，不能修改他人的价格或库存。没有商家审核。

## 折扣和数据范围

- 原价小计满 100 元整单减 10 元，仅一次。
- 优惠码 `STUDENT10`：在满减后的金额上再减 10%，优惠额四舍五入保留两位小数。
- 例如 P02 单价 12.50 元、8 件，小计 100.00，实付 81.00 元。
- 每种商品累计数量 1–99；修改为 0 表示删除。空车不可结账。
- 报价后输入 `y` 才模拟结账并清空当前账号的购物车，取消时保留。
- 销售者修改价格后，消费者购物车按最新目录价计算；结账前显示当前应付金额。
- 账号及角色存于 `data/users.properties`，重启后仍可登录。
- 商品、归属、价格、库存和已完成订单保存到 `data/store.properties`，重启后保留。
- 购物车暂存在内存中，退出程序后清空；仅退出登录时仍保留，不同消费者之间隔离。

## 项目结构和团队职责

```text
src/Main.java          IDEA 启动入口
src/shop/Main.java     中文菜单、注册登录交互、角色分流
src/shop/Role.java     销售者和消费者枚举

src/shop/Product.java  不可变商品
src/shop/Catalog.java  商品归属、库存管理、购买事务、订单查询
src/shop/Order.java    不可变订单及销售者明细视图
src/shop/StoreFile.java 商品库存和订单的原子文件保存

src/shop/Cart.java     购物车数量校验和小计
src/shop/Checkout.java 折扣规则和收据快照
```

可按「账号与权限」「商品管理」「购物车与结账」「菜单、测试与文档」划分团队职责。每个功能分支提交后发 PR，请其他成员审查，测试通过再合并到 main。

## 安全设计

密码使用 PBKDF2-HMAC-SHA256（600,000 次迭代、每个账号独立随机盐）计算摘要；文件不存明文密码。账号文件和本地构建产物已被 Git 忽略，不应提交仓库。系统终端支持隐藏密码；IDEA 控制台输入可能可见，程序会提示。

角色在注册时保存，只能凭正确密码获取会话；会话构造器私有，注销后失效。销售者权限在商品管理业务层再次校验，消费者不能绕过菜单改价。金额用 BigDecimal，商品编号和数量进行校验。

这是本地单进程课堂演示，数据文件受运行机器的文件权限保护。同一数据目录通过文件锁防止多进程同时运行；商店服务内的购买事务串行处理。没有找回密码、登录限流、真实支付、退款、物流或在线服务端。账号和订单数据目录已由 Git 忽略，不要上传。

## 库存与订单规则

- 新商店不预置无主商品，请先登录销售者添加商品（包含初始库存）。旧版本商品仅存在内存，无法恢复；原账号文件不变。
- 商品编号在整个商店中唯一。每个商品库存为 0–1000000；单个购物车每种商品仍最多 99 件，并且不能超过可售库存。
- 重复加购按累计数量检查；修改购物车数量也检查库存。库存为 0 时列表显示 `Sold out`，购买会被拒绝，购物车中的售罄项仍可删除。
- 加购不预占库存；他人购买或销售者调低库存后，旧购物车可能超过当前库存，此时结账会再次拒绝并提示处理。
- 结账前显示最新价格；确认时再检查价格、库存和购物车归属。全部通过后，原子保存库存和订单，再清空购物车。任何商品不足或保存失败均不部分扣库、不产生订单、不清空购物车。
- 跨销售者购物车仍使用整单折扣，按各明细原价比例分摊实付；采用累计分配处理分币舍入，各销售者实收之和等于消费者实付。
- 销售者在「我的订单」只看到售出自己商品的明细、购买人、时间、数量、当时单价和自己的实收。消费者在「历史购买记录」看到自己的整单明细及实付。
- 订单保存购买时的快照，之后改价和补货不会改变历史记录。取消结账不算订单。

## 推荐演示顺序

1. 注册两个销售者和两个消费者，密码自行设置。
2. 销售者 A 添加 P01（单价 50.00，库存 2）；销售者 B 添加 P02（单价 20.00，库存 1）。
3. 尝试用 B 修改 P01，观察「只能管理自己的商品」提示。
4. 消费者尝试购买 3 件 P01，观察库存不足；改为 2 件 P01 和 1 件 P02。
5. 使用 STUDENT10，应付 99.00。先取消，确认库存不变；再次结账确认，生成订单并扣库存。
6. 商品库存变为 0，显示 Sold out，再次加购会被拒绝。
7. A 查看订单，只看到 P01，实收 82.50；B 只看到 P02，实收 16.50。购买者历史记录显示整单 99.00，另一消费者看不到这笔订单。
8. 重启程序，验证原账号、库存、商品和历史订单仍保留。
9. 执行 `.\run.ps1 -Test`，运行 96 项检查，涵盖越权、超库存、库存争抢、重启和保存失败回滚。
